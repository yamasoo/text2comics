## 2. project.yaml

| 欄位 | 必填 | 預設 | 說明 |
|---|---|---|---|
| `title` | 是 | — | 作品名 |
| `language` | 否 | `zh-TW` | 台詞語言 |
| `reading` | 否 | `rtl` | 閱讀方向；目前只支援 `rtl`（日式右翻） |
| `style_preset` | 否 | `mono` | 畫風預設集：`mono`（日式黑白頁漫）／`color`（彩色日式頁漫）／`american`（美式彩色漫畫）。見第 18 節 |
| `style` | 否 | 預設集的 | 整部作品共用的畫風（英文），放在每格 caption 的最前面；明寫就蓋掉預設集那一欄 |
| `meta` | 否 | 預設集的 | MOSS 的 `summary.meta`；明寫就蓋掉預設集那一欄 |
| `megapixels` | 否 | `1.0` | 每格生圖的總像素（百萬） |
| `negative` | 否 | 空 | 負向提示詞（CFG 1 時無效） |
| `sfx_mode` | 否 | `overlay` | `overlay`：狀聲詞由嵌字疊上；`moss`：交給 MOSS 畫 |
| `candidates` | 否 | `1` | 每格幾個 seed |
| `seed_base` | 否 | `0` | 加到每個 seed 上；整部作品想全部換一批 seed 時改這個 |
| `comfy_profile` | 否 | `config.json` 的 `comfy.default_profile` | 這一部作品用哪一組出圖 profile（`config.json` 的 `comfy.profiles` 其中一組，例如 `moss`、`anima`）。見第 17 節 |
| `output` | 否 | 保留原色 | 組版的輸出設定：`{gray: true}` 把每張候選圖轉灰階（PDF／CBZ 變小，黑白頁漫常用）；省略或 `false` 就保留原色。**不依畫風預設集自動判斷**——1.12.1 試過會把沒寫 `style_preset` 的舊專案誤判成黑白。見第 18 節 |
| `layout` | 否 | 用內建的 `t2c/data/pages.json` | 這一部作品自己的版型：`{file, mode}`（`file` 相對專案資料夾；`mode` 是 `merge` 疊加或 `replace` 覆寫，省略＝`merge`）。也可以只寫檔名字串。見第 6 節 |

## 3. 視覺聖經

Markdown＋YAML frontmatter（與 Novel Studio 的設定集同一種寫法）。frontmatter 給程式，本文給人看。

### 角色 `bible/characters/<id>.md`

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | 是 | `[a-z0-9_-]`，分鏡用這個指角色；檔名建議同 id |
| `name` | 是 | 顯示名稱 |
| `aliases` | 否 | 其他稱呼（S5 給 LLM 對應原著用） |
| `sections` | 是（或 `look_en`） | **分段外觀**（步驟 2）：`{head, body, upper, lower, accessory}`，每一段是英文短語清單（不是句子）。有 `sections` 就用它，沒有才退回 `look_en`。生圖時依分鏡的 `shot` 選段貼上（見下面「按鏡頭選段」） |
| `look_en` | 舊格式 | 整段英文外觀。有 `sections` 的卡片可以沒有這一欄；`t2c/look.look_en()` 會把五段接起來給 LLM 上下文與卡片清單用 |
| `outfits` | 否 | `{服裝 id: {top: […], bottom: […], set: […], notes: 中文}}`（步驟 2）或舊的 `{服裝 id: 英文完整句}`。`default` 是預設服裝；id 用 `[a-z0-9_-]`。每一項是英文短語（顏色、款式、配件），不寫表情、動作 |
| `outfit_notes` | 否 | `{服裝 id: 中文說明}`，給人看（S6；程式不用，服裝矩陣會列出） |
| `status` | 否 | `draft`／`confirmed`（S6）。只在 `bible/drafts/` 用 `draft`；`accept` 搬進正式資料夾時改成 `confirmed`。舊卡片沒有這欄＝已確認 |

`look_en` 的檢查規則（`tools/bible.py check`，S6）：必須是英文、至少 6 個字、有性別字（man／woman／boy／girl…）與年齡字（young／middle-aged／mid-twenties…）；不得含服裝、表情、動作的字（清單在 `t2c/bible_check.py`）；沒提到頭髮只警告；超過 60 字警告。服裝缺 `default` 是錯誤。
### 按鏡頭選段（步驟 2）

分鏡已經有 `shot` 欄位，所以只要一張對照表（`t2c/look.SHOT_SECTIONS`／`SHOT_OUTFIT`）。特寫送全身外觀會稀釋提示詞；同一個角色的臉在任何鏡頭都來自同一段 `head` 文字，一致性反而更好。

| 分鏡的 `shot` | 送出去的段 |
|---|---|
| `extreme_close` | `head` |
| `close` | `head`、`accessory` |
| `medium` | `head`、`upper`、`accessory`、上著（`outfits.<id>.top`） |
| `full`、`wide` | `head`、`body`、`upper`、`lower`、`accessory`、上著、下著 |
| `extreme_wide` | 全部，含套裝名稱（`set`） |

沒有 `sections` 的舊卡片一律貼整段 `look_en`（不受 shot 影響）。

### 出圖指紋與過期（步驟 2、D1）

出圖時每一格的 job 多兩個欄位，跟著 `build/chNNN/<格 id>.prompt.json` 一起存下來：

- `fingerprint`：`{"style": 畫風指紋, "shot": 這一格用的 shot, "characters": {角色 id: {"outfit": 服裝 id, "parts": {段名: 指紋}}}, "location": 地點指紋, "prompt": 提示詞指紋}`。「段名」是 `head`／`body`／`upper`／`lower`／`accessory`／`outfits.<id>.top`…，正是「哪一段改了」的答案。
- `explore`：這一格用到、但解析失敗又沒有 `extra` 旗標的角色 id 清單（**待補的具名角色**）。**探索用**的格不進 `picks/`、不進頁面、也不列入過期清單
- `unresolved`：`explore` 每一項的原因與建議，`[{"id": "hynesen", "suggest": ["ale_heinessen"]}]`。建議只給人看（`difflib`），程式不會自動套用（決策 D11）；補上卡片後再正式出圖。

「過期」＝拿現在的卡片重算一次指紋，跟出圖當時記下來的不一樣（`t2c/stale.py`）。`GET /api/bible/stale` 回過期清單與原因，`POST /api/task/render` 帶 `stale: true` 只重畫那些格。seed 由格 id 決定所以可重現，但提示詞變了圖一定變，那是預期。

### 地點 `bible/locations/<id>.md`

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id`、`name` | 是 | 同上 |
| `look_en` | 是 | 固定的英文場景描述；不得出現人物字（person、man、crowd…，S6 檢查） |
| `outfit_notes`、`status` | 否 | 地點沒有服裝；`status` 同角色 |

卡片本文（frontmatter 之後）給人看，程式不讀。S6 產生的草稿本文固定有：摘要、`## 待確認`（補上的、與設定衝突的）、`## 登場章節`、`## 原文依據`（每條外觀都附原文逐字引文）。
## 4. 漫畫劇本 `script/chNNN.md`

給人讀、給人改的版本，也是**分鏡階段的唯一依據**：分鏡的台詞、旁白、狀聲詞必須和劇本逐字相同（S5 會檢查），所以要改台詞就改劇本，再重跑分鏡。S5 由 LLM 依改編規劃逐頁產生（`t2c/script.py` 解析）。

```markdown
---
chapter: 1
title: 章名
source: source/ch001.txt
pages: 頁數
---

# 第 1 話　章名

## 第 1 頁（模板 5a：上二中一下二）

**1 格**｜遠景、俯視｜畫面描述。
- 旁白：……
- 角色名：台詞
- 角色名（心聲）：……
- 角色名（喊）：……
- 角色名（通訊）：透過通訊器、電話傳來的聲音
- 角色名（畫面外）：人在附近、但這一格沒畫到他
- 狀聲詞：碰！

**2 格**｜特寫｜畫面描述。
- （無台詞）
```

| 項目 | 寫法 |
|---|---|
| 頁標題 | `## 第 N 頁（模板 K：名稱）`；模板 key 必填（名稱可省略），S5 產生時由程式統一寫法 |
| 格標題 | `**N 格**｜鏡頭詞、角度詞｜畫面描述`；N 依序是 1–模板格數 |
| 鏡頭詞（選一個） | 大遠景＝`extreme_wide`、遠景＝`wide`、全身＝`full`、中景＝`medium`、近景＝`close`、特寫＝`extreme_close` |
| 角度詞（可省略） | 平視＝`eye`、俯視＝`high`、仰視＝`low`、鳥瞰＝`bird`、斜角＝`dutch`、過肩＝`over_shoulder` |
| 台詞 | `- 角色名：台詞`，角色名是聖經的 `name`、`aliases` 或 id |
| 語氣標記 | `（心聲）`→ thought、`（喊）`／`（喊叫）`→ shout、`（小聲）`／`（悄聲）`→ whisper；沒標記是一般台詞（分鏡可依內容判斷成 speech、shout 或 whisper） |
| 聲音來源標記（M1 修正） | `（通訊）`／`（電話）`／`（廣播）`／`（無線電）`→ radio：透過機器傳來的聲音，說話的人通常不在這一格（分鏡用 `offscreen: true`）；不能再加語氣。`（畫面外）`→ 說話的人不在這一格的畫面裡（分鏡用 `offscreen: true`），可以和喊、小聲併用，寫成 `（畫面外、喊）`；不能和心聲併用 |
| 旁白、狀聲詞 | `- 旁白：…`（narration）、`- 狀聲詞：…`（或 `音效`） |
| 沒有台詞 | `- （無台詞）` |
| 限制 | 每格最多 3 個對話框（旁白算、狀聲詞不算）；一個對話框 45 字內；說話者要有角色卡（畫面外、通訊的也要） |

描述換行會併進同一格的描述。分鏡的鏡頭與劇本不一致只會提醒，不擋。

## 5. 分鏡 `storyboard/chNNN.json`

```json
{
  "version": 1,
  "chapter": 1,
  "title": "章名",
  "pages": [
    {
      "page": 1,
      "template": "5a",
      "panels": [
        {
          "slot": 1,
          "id": "p001_k1",
          "shot": "wide",
          "angle": "high",
          "location": "rooftop",
          "scene": "英文：這一格發生什麼事（不寫角色外觀）",
          "characters": [
            {"id": "lin", "outfit": "default", "pose": "英文姿勢", "expression": "英文表情", "box": [0.55, 0.45, 0.8, 0.9]}
          ],
          "objects": [{"caption": "英文物件描述", "box": [0.1, 0.1, 0.3, 0.3]}],
          "sfx": [{"text": "碰！", "box": [0.75, 0.05, 0.98, 0.4]}],
          "bubbles": [{"kind": "speech", "speaker": "lin", "text": "台詞", "anchor": [0.5, 0.2]}],
          "seeds": []
        }
      ]
    }
  ]
}
```

### 格（panel）欄位

| 欄位 | 必填 | 說明 |
|---|---|---|
| `slot` | 是 | 模板裡的格子編號（1 開始）；一頁的 slot 必須剛好是 1…模板格數 |
| `id` | 否 | 預設 `p<頁3位>_k<slot>`；檔名都用它。整章不能重複（頁碼也不能重複），存檔時擋 |
| `shot` | 否 | `extreme_wide`、`wide`、`full`、`medium`（預設）、`close`、`extreme_close` |
| `angle` | 否 | `eye`（預設）、`high`、`low`、`bird`、`dutch`、`over_shoulder` |
| `location` | 否 | 地點 id；有寫就把地點的 `look_en` 放進 caption，並加一個全畫面的背景 item |
| `scene` | 是 | 英文，這一格的畫面內容。**不寫角色外觀**，用 the young woman 之類的代稱 |
| `characters` | 否 | 在場角色。同一格同一角色只能一次。沒有人就給 `[]` |
| `characters[].id` | 是 | 角色卡的 id、姓名或別名都可以（解析順序：精確 id → 姓名 → 別名 → 正規化：NFKC、大小寫、空白、連字號與底線；實作在 `t2c/cast.py`，決策 D12）。**解析失敗又沒有 `extra`** 才標成探索用 |
| `characters[].extra` | 否 | `true`＝臨時角色（龍套，決策 D9）。沒有卡片也能出圖與選圖，編譯貼通用外觀（`An unnamed minor character with a plain generic appearance`，不猜性別髮型），指紋記成 `extra:<id>`。有卡片時這個旗標沒有作用 |
| `characters[].box` | 否 | 比例框；省略時是畫面中間。**一格有 2 個以上角色時**，編譯會依框的中心點在該角色 caption 最前面加 `He/She is on the left/right side of the frame.`（中心 <0.4 為左、>0.6 為右，其餘為中間）。`over_shoulder` 會把背對鏡頭的角色放到前景左側而壓過 box（S1 實測），要用的話把背對鏡頭的角色 box 放左邊 |
| `objects` | 否 | 重要物件 |
| `sfx` | 否 | 狀聲詞；`sfx_mode = moss` 時才送進生圖 |
| `bubbles` | 否 | 對話框（**永遠不送進生圖**，給嵌字用），依閱讀順序排列，一格最多 3 個（S5 檢查）。`kind`：`speech`（橢圓）、`thought`（雲狀，尾巴是小圓點）、`shout`（爆炸形）、`whisper`（虛線橢圓）、`radio`（細密鋸齒外框的電子音框：通訊、電話、廣播）、`narration`（旁白方框，沒有尾巴）；`speaker` 必須是這一格在場的角色（旁白免填；畫面外的見下面「畫面外的說話者」），尾巴指向他的臉；`offscreen`（選填，預設 `false`）也見該小節；`anchor` 是對話框中心的**希望位置**，嵌字會從這裡出發，避開臉、其他對話框，找最近的空位。台詞裡的換行 `\n` 會強制換到下一行（直排時是下一欄）。嵌字沒有中文斷詞，S5 要求每行 ≤ 12 字（旁白 ≤ 16），超過要在詞與詞之間加 `\n` |
| `seeds` | 否 | 手動指定 seed；不夠的由格子 id 自動補 |

### 畫面外的說話者（M1 修正）

說話的人不在這一格的畫面裡——人在畫面外，或是透過通訊、電話從別處傳來——時，對話框加 `"offscreen": true`：

```json
{"kind": "radio", "speaker": "zhou_yuan", "offscreen": true, "text": "在。", "anchor": [0.6, 0.1]}
```

| 規則 | 說明 |
|---|---|
| `speaker` | 仍然必填，必須是聖經裡的角色，但**不可以**列在這一格的 `characters`（列了就是畫出來了，兩者矛盾） |
| 生圖 | 畫面外的說話者不送進生圖：不加 character item、不算進「exactly N people」 |
| 種類 | `speech`、`shout`、`whisper`、`radio` 可以；`thought`（心聲要看得到人）、`narration`（本來就沒有說話者）不行 |
| 尾巴 | `speech`、`shout`、`whisper`：指向離對話框最近的格框邊（左右兩邊優先），表示聲音從畫面外來；`radio`：沒有尾巴（鋸齒框本身表示電子音）。都可以在嵌字微調裡改 |
| `radio` 但說話者在畫面上 | 例如臉出現在螢幕上：不寫 `offscreen`，把他列進 `characters`，尾巴照常指向他 |
| 和劇本的對應 | 劇本 `（通訊）` → `kind` 必須是 `radio`；劇本 `（畫面外）` → 必須 `offscreen: true`。劇本沒標、分鏡自己決定不畫出說話者（例如只拍聽的人）也可以，加 `offscreen: true` 即可 |

### 座標

一律是比例 `[x0, y0, x1, y1]`：左上角 (0,0)、右下角 (1,1)，相對於**這一格**（不是整頁）。`anchor` 是 `[x, y]`。

精確地說，分鏡裡的座標（`characters[].box`、`objects[].box`、`sfx[].box`、`bubbles[].anchor`）都是相對於**這一格生成的圖**。組版時圖會依 `picks` 的 `focus`、`zoom` 裁切成格子的形狀（第 8 節），嵌字會把這些座標換算到裁切後的格子上，所以改了裁切，對話框與臉框會跟著圖走。沒有放大、焦點置中時，兩者幾乎相同。

## 16. 切對話 `scenes/chNNN.json`（N3）

（節號排最後：前面各節的編號不動，`t2c/` 的註解與 `CHANGELOG.md` 裡的「第 N 節」引用才不會失效；這一節放在劇本、分鏡旁邊，因為流程上前後相接。）

小說的一章 → 場 → 旁白／對話／演出。每一行都帶 `source_para` 回指原著段落，所以後面劇本與分鏡的台詞只有這一個來源。

### 檔案與產生方式

```
<專案>\scenes\chNNN.json                     產出：場、行、source_para（人可以改，進版控）
<專案>\build\adapt\chNNN_scenes_fidelity.md  忠實度報告（不進版控）
<專案>\build\adapt\chNNN\annotate_整章.txt   模型最後一次輸出（不進版控；回修失敗時看這裡）
```

`t2c/adapt.py` 的 `Adapter.run_annotate(chapter, title_hint="", force=False, repair=True)`：「產生 → 驗證 → 回修」走其他階段同一條 `_generate()`（沒過就把全部錯誤回給模型，最多 `max_fix` 次），過了再跑漏句修補、寫檔與報告，回傳 `(scene_doc, report)`。路徑由 `Project.scenes_path()` 決定；檔案已存在要 `force=True` 才會覆蓋。模型階段名稱是 `annotate`（`adapt.STAGE_KEY`），`config.json` 的 `stage_providers`／`reasoning` 就用這個鍵。

### 完整範例

（章節是虛構的，只示範寫法；`//` 是說明，實際檔案沒有這些行。這一份跑得過 `annotate.validate()`，也轉得成分鏡。）

```json
{
  "version": 1,                                      // 格式版本（annotate.SCHEMA_VERSION，目前 1）
  "chapter": 3,                                      // 章號：這一份是 scenes/ch003.json
  "title": "天台的便當",                              // 章名；沒有就空字串
  "source": {"file": "ch003.txt", "paragraphs": 3},  // 這一份是從哪個原著切出來的：檔名與段數
  "scenes": [                                        // 至少一場，最多 60 場
    {
      "scene_id": "ch003_sc01",                      // 程式給的 id：ch<章3位>_sc<場2位>
      "title": "天台的便當",                          // 這一場的短標題（選填，中文）
      "location": "rooftop",                         // 地點 id，要在 bible/locations；沒有合適的就 null
      "setting_en": "The rooftop of a school club building at noon; a water tank casts a hard shadow.",
                                                     // 英文，這一場看得見的畫面（會進生圖提示詞）
      "cast": [                                      // 這一場出場的角色
        {"id": "lin", "expression": "annoyed"},      // expression 選填，英文表情
        {"id": "hao"}                                // 沒有特別的表情就只寫 id
      ],
      "lines": [                                     // 依原著順序；旁白、對話、演出三種
        {"type": "narration", "text": "十二點四十分。", "source_para": 1},
        {"type": "direction", "shot": "wide", "angle": "high", "note": "An empty rooftop under the noon sun."},
        {"type": "dialogue", "speaker": "lin", "kind": "whisper", "text": "「……又不接。」", "source_para": 2},
        {"type": "narration", "text": "她小聲嘀咕，把手機拿下來。", "source_para": 2},
        {"type": "narration", "text": "曉雨沒有回頭。", "source_para": 3},
        {"type": "narration", "text": "她雙手抱胸，把臉別向另一邊。", "source_para": 3}
      ]
    }
  ]
}
```

透過通訊器、電話、廣播的聲音，或說話的人不在畫面裡，對話行多一個 `offscreen`（規則同第 5 節「畫面外的說話者」）：

```json
{"type": "dialogue", "speaker": "hao", "kind": "radio", "offscreen": true, "text": "「我到了。」", "source_para": 2}
```

### 欄位

**最外層**

| 欄位 | 必填 | 說明 |
|---|---|---|
| `version` | 是 | 格式版本，目前 `1`（`annotate.SCHEMA_VERSION`） |
| `chapter` | 是 | 章號 |
| `title` | 是 | 章名；沒有就空字串 |
| `source.file` | 是 | 原著檔名（`source/chNNN.txt`） |
| `source.paragraphs` | 是 | 原著切成幾段；`source_para` 只能是 1 到這個數字 |
| `scenes` | 是 | 至少一場，全章最多 60 場（`MAX_SCENES`） |

**場（scene）**

| 欄位 | 必填 | 說明 |
|---|---|---|
| `scene_id` | 是 | `ch<章3位>_sc<場2位>`，程式依場序產生 |
| `title` | 否 | 這一場的短標題（中文）；模型沒寫就不會有這個鍵 |
| `location` | 否 | 地點 id 或 `null`（程式一律會寫這個鍵）；寫了必須在 `bible/locations` |
| `setting_en` | 是 | 英文一到兩句：時間、光線、空間、天氣。**不寫角色外觀**（那是視覺聖經的 `look_en`、`outfits`）；含中文會被擋 |
| `cast` | 是 | 這一場出場的角色；`[]` 也可以 |
| `cast[].id` | 是 | 角色 id，必須在 `bible/characters`；同一場不能重複 |
| `cast[].expression` | 否 | 英文表情，只給這一場用；含中文會被擋 |
| `lines` | 是 | 依原著順序的行；不能是空的 |

**行（lines）**

| `type` | 欄位 | 說明 |
|---|---|---|
| `narration` | `text`、`source_para` | 旁白；`text` 是原著該段的原文（可以只是其中一個子句） |
| `dialogue` | `speaker`、`kind`、`text`、`source_para`；`offscreen` 選填 | `speaker` 要是聖經角色且列在這一場的 `cast`；`text` 連引號逐字照抄；`kind` 是 `speech`（預設）、`thought`、`shout`、`whisper`、`radio`；`offscreen: true` 表示說話的人不在畫面裡 |
| `direction` | `shot`、`angle`、`note`（至少一個） | 演出；只決定後面幾行怎麼拍，不算台詞，也沒有 `source_para` |

`shot`：`extreme_wide`、`wide`、`full`、`medium`、`close`、`extreme_close`；`angle`：`eye`、`high`、`low`、`bird`、`dutch`、`over_shoulder`（同第 5 節）。`note` 是英文的一句話重點。

### source_para：原著段落號

- 段落由 `annotate.split_paragraphs()` 切：空行分段；Markdown 標題行（`# …`）不算內容、純分隔線（`＊＊＊`、`——`、`===`）也不算，兩者都不佔段號；同一個段落裡的換行會併成同一段。第 1 段是 1。
- 意思就是「這一行是從原著第幾段抄來的」。程式靠它做逐字比對、覆蓋率、漏句修補與順序檢查；`paragraph_map()` 可以把它還原成段落文字。
- 台詞與旁白照原著順序：段落號只能往前或持平，不能回到前面的段落。

### 模型輸出的 op

模型寫的不是 `lines`，而是「一場一串指令」（`ops`），由 `annotate.expand()` 展開成上面的場與行：

```json
{"scenes": [
  {"title": "天台的便當", "location": "rooftop",
   "setting_en": "The rooftop of a school club building at noon.",
   "cast": [{"id": "lin", "expression": "annoyed"}],
   "ops": [
     {"k": "N", "p": 1},
     {"k": "x", "shot": "wide", "angle": "high", "note": "An empty rooftop under the noon sun."},
     {"k": "n", "p": 2, "t": "她小聲嘀咕"},
     {"k": "d", "p": 2, "s": "lin", "m": "小聲", "t": "「……又不接。」"}
   ]}
]}
```

| `k` | op 的欄位 | 展開成 |
|---|---|---|
| `N` | `p` | 第 `p` 段整段旁白（原文照抄）；這一段裡有引號台詞時不能用，要拆成 `n` 加 `d` |
| `n` | `p`、`t` | 段落裡的敘述片段，`t` 是該段原文的子句 → 一到多行 `narration` |
| `d` | `p`、`s`、`t`（`m` 選填） | 一句對話 → 一行 `dialogue`；`s` 是說話的角色 id，`t` 連引號逐字照抄 |
| `x` | `shot`、`angle`、`note`（至少一個） | 一行 `direction`，不算台詞 |

- 長句由 `split_text()` 斷：句末（。！？）斷句、短句併到約 60 字、超過 90 字在逗號斷，所以一個 `N` 常會變成好幾行 `narration`。
- `m`（括號標記）沿用劇本那一套：`心聲`、`喊`、`喊叫`、`小聲`、`悄聲`、`通訊`、`電話`、`廣播`、`無線電`、`畫面外`；要併寫用「、」（例：`畫面外、喊`）。`通訊` 這類聲音一律變 `radio`，不能再加語氣；`心聲` 不能標 `畫面外`。
- 說話的人漏列在 `cast` 時，程式會自動補進該場 `cast`（op 有寫 `e` 就用它的英文表情），並在 `adapter.warnings` 留一條。
- 模型不寫 `scene_id`，由程式依場序產生。

### 驗證規則

`expand()`（模型輸出）與 `validate()`（寫好的檔案、人改過的）用同一組規則；有 error 就把全部錯誤回給模型修，沒過就不寫檔：

| 規則 | 內容 |
|---|---|
| 逐字 | 旁白、對話的 `text` 要是該段原文的子句：忽略標點，允許句首補一個代名詞當主詞（「雙手抱胸」寫成「她雙手抱胸」可以）；改寫、漏字、自己編都不行 |
| 段落全覆蓋 | 原著每一段都要出現在某一行的旁白或對話裡；漏掉就退回，訊息會列出段號（例：`原著有 2 段沒用到：4、7–9`） |
| 順序 | 段落號只能往前或持平（同一段可以拆成多行），不能回到前面的段落 |
| 場 | 一場至少要有一行旁白或對話（只有演出不算）；一場最多涵蓋 35 段（`MAX_SCENE_PARAGRAPHS`）；全章最多 60 場 |
| 聖經 | `cast` 與 `speaker` 必須在 `bible/characters`；`location` 必須在 `bible/locations` |
| 英文欄位 | `setting_en`、`cast[].expression`、`direction.note` 一律英文，含中文就擋（這些會進生圖提示詞） |
| 對話種類 | `speech`、`thought`、`shout`、`whisper`、`radio`；`offscreen` 只能是 true 或 false，`thought` 不能標 `offscreen` |
| 演出 | `direction` 至少要有 `shot`、`angle`、`note` 其中一個，值要在上面的列舉裡 |
| 轉得過分鏡 | 展開後先試轉一次分鏡，再跑 `check.check_page_panels()`（模板格數、slot 順序、對話框數量與每欄字數…）；轉不過就當成 error 退回 |
| 漏敘述（提醒） | 某段有整句敘述沒進任何一行 → `warn`，不擋（交給漏句修補）：`漏掉敘述「…」；預設會由漏句修補照原文補回` |

### 漏句修補

`run_annotate()` 在驗證通過後跑 `annotate.repair_omissions()`（`repair=False` 可以關掉）：把每一段漏掉的**敘述**原文照順序補成 `narration` 行，不經過模型、不動台詞；補的行依原文順序插在該段落現有的行之間，句尾不留逗號。重跑不會重複補（第二次回傳 0），補了幾行會寫進報告。想自己安排就用 `n` op 先補，程式沒抓到的漏句不會動手。

### 忠實度報告

`build/adapt/chNNN_scenes_fidelity.md`，程式自己算、不呼叫模型：

```
# 切對話忠實度報告：天台的便當

- 原著段落 10 段，用到 10 段（覆蓋 100%）
- 對話 4 句，其中 4 句能在原著逐字找到（不計標點）
- 原著引號內台詞 5 句，其中 5 句進了切對話
- 逐字違規 0 句；漏掉的敘述子句 0 句；漏句修補補了 2 行
```

| 指標 | 意思 |
|---|---|
| 段落覆蓋 | `paragraphs_used`／`paragraphs`；切對話要求 100% |
| 對話逐字 | `dialogue_found`／`dialogue_lines`：整句比不到就依句讀拆開再比（`script.found_in()`），改寫的仍會列出來 |
| 原著引號台詞保留 | `source_quotes_kept`／`source_quotes`：原著引號裡去掉標點後至少 3 個字的句子，有幾句進了切對話 |
| 逐字違規、漏敘述、補了幾行 | `unfaithful`、`omitted`、`repaired` 的數量 |

再往下是四份清單（有才出現）：切對話有、原著找不到的台詞；逐字違規的子句；原著有、切對話沒有的台詞；原著有、切對話沒有的敘述子句（漏句）。前兩項指標和劇本階段的 `build/adapt/chNNN_fidelity.md` 是同一套算法，改劇本前後可以直接比。

### 轉成分鏡：to_storyboard 與 compile_chapter

`annotate.to_storyboard(project, scene_doc, pages_data=None, plan=None, compile_check=True)` 把場轉成第 5 節的分鏡：

- `lines` 依序變成一格一格的 `bubbles`：台詞逐字複製，程式只負責直排斷行（對話一欄 11 字、旁白 15 字，上限是每欄 12／16 字，留一個字的空間給標點）、`anchor` 依閱讀順序排、角色框左右分開。
- 一行 `direction` 套用到它後面出現的每一行，直到下一個演出；都沒有就依 `medium`、`eye`。
- `offscreen` 與 `radio` 的對話框不畫說話的人（同第 5 節）。
- 沒給 `plan` 就依行數自動配頁（一頁最多 6 格、一格最多 3 個對話框）；給改編規劃（第 12 節）就先用它的 `template`，頁數不夠再自動補。
- `compile_check=True` 會真的呼叫 `compile_chapter()`，通過才回傳，所以轉出來的東西保證能編譯。

流程上有兩條路：切對話 →（`to_storyboard`）→ 分鏡 → `compile_chapter()`，不寫劇本也能出分鏡；或把 `scenes/chNNN.json` 當台詞帳本餵劇本階段（`prompts.scenes_ledger()` 會排成 `- lin（小聲）：「……又不接。」〔p3〕`），寫完劇本再照劇本產生分鏡。兩條路的台詞都來自同一份檔案。

## 6. 格子模板 `t2c/data/pages.json`（＋專案自己的版型檔）

- `page`：頁面比例（B5，182×257 mm）、輸出寬度、頁邊（比例，[左, 上, 右, 下]）、格間白邊與框線粗細（像素）。
- `templates.<key>.panels`：格子框，比例座標、相對於頁面內框，**依右翻閱讀順序排列**（右上開始、同排由右到左、再下一排）。格子彼此相接，白邊在組版時才扣。

目前內建模板：`1`（全頁）、`2h`、`3a`、`4a`、`5a`、`6a`。新增模板要讓格子剛好鋪滿（測試會檢查）。

**專案層的版型（N4）**：`project.yaml` 寫

```yaml
layout:
  file: pages.json      # 相對專案資料夾，或完整路徑
  mode: merge           # merge（預設，疊加）或 replace（覆寫）
```

- `merge`：專案檔的模板加進內建模板；同名的換掉（位置不變），新的排在後面。
- `replace`：只用專案檔的模板，內建的 `1`、`5a` 等看不到。
- `page` 一律「專案檔有給的欄位才蓋掉、沒給的沿用內建」（一層合併），所以只想改輸出寬度就只寫 `"page": {"width_px": 1400}`。
- 專案檔可以只寫 `templates`，也可以只寫 `page` 裡的幾個欄位；`_` 開頭的鍵（例如 `_說明`）會被略過。
- 檢查：檔案存不存在、JSON 語法（會指出第幾行第幾欄）、`templates` 不能是空的、模板 key 只能用 `a-z0-9_-`、每個 `panels` 至少一格且是 0–1 的比例框、`page` 的尺寸與頁邊。錯誤訊息會寫出**哪個檔案、哪個模板、第幾格**。
- 讀專案版型的地方：`Project.pages()`。編譯、組版、檢查、規劃檢查、介面（模板下拉、頁面尺寸）都用它；`layout.load_pages()` 仍然讀單一檔案（內建那份）。

## 7. 編譯結果 `build/chNNN/<格 id>.prompt.json`

| 欄位 | 說明 |
|---|---|
| `id`、`page`、`slot` | 對應分鏡 |
| `rect_px` | 這一格在整頁上的像素框（組版用） |
| `width`、`height` | 生圖尺寸 |
| `layout` | 送給 MOSS 的 layout JSON（展開，方便人看） |
| `negative` | 負向提示詞 |
| `seeds` | 這一格要跑的 seed |

送給 ComfyUI 的正向提示詞就是 `json.dumps(layout, ensure_ascii=False)`。

## 8. 選圖紀錄 `picks/chNNN.json`（S2）

人的決定（選哪張、構圖怎麼裁），所以放在專案根目錄的 `picks/`、進版控；不要放進 `pages/`（那是產出，不進版控）。

```json
{
  "version": 1,
  "chapter": 1,
  "picks": {
    "p001_k1": {"image": "p001_k1_s1390808158.png", "focus": [0.5, 0.5], "zoom": 1.0}
  }
}
```

| 欄位 | 必填 | 預設 | 說明 |
|---|---|---|---|
| key（格 id） | — | — | 分鏡裡的格 id（`p001_k1`） |
| `image` | 是 | — | `renders/chNNN/` 底下的檔名（純檔名，不含路徑）。草稿與定稿是不同的檔，所以記檔名而不是 seed |
| `focus` | 否 | `[0.5, 0.5]` | `[x, y]` 比例，原圖上要盡量留在裁切框中央的點（0,0 是左上） |
| `zoom` | 否 | `1.0` | 1–4。1 是剛好蓋滿格子（cover）；大於 1 再放大，只留焦點附近 |

### 裁切規則（cover）

1. 縮放到剛好蓋滿格子（取寬、高兩個縮放比的較大者），再乘上 `zoom`。
2. 裁切框中心盡量對準 `focus`；框不會超出原圖，所以焦點靠近邊緣時，框會被推回圖內。
3. 沒有在 picks 裡的格：暫用 `renders/chNNN/` 裡該格第一個候選（`<格 id>_s<數字>.png`，依檔名排序），並在結果裡列警告；一張都沒有就畫灰底佔位格。

### 組版規則

- 頁面用 `t2c/data/pages.json` 的 `page`：寬 `width_px`、高依 B5 比例；內框 = 扣掉 `margin`。
- 每格框 = 模板格子（比例）換算成像素，相鄰兩格之間留 `gutter_px`（一格各扣一半）；貼圖後在格子邊緣畫 `frame_px` 的黑框（畫在格子內側，不會吃掉白邊）。
- 預設輸出灰階（模式 `L`）：消除 S1 看到的輕微偏色。`--color` 保留原色。
- PNG 內附 dpi（由頁寬 mm 與像素換算）。

## 10. 嵌字微調 `letters/chNNN.json`（S3）

嵌字預設全自動：依分鏡的 `anchor` 找位置、從 `characters[].box` 推估臉的位置來避開、尾巴指向說話者的臉。自動結果不滿意時，在介面拖曳（或手改這個檔），覆寫只記**和自動不同的部分**。跟 `picks` 一樣是人的決定，放在專案根目錄的 `letters/`、進版控。

```json
{
  "version": 1,
  "chapter": 1,
  "panels": {
    "p001_k5": {
      "faces": [[0.05, 0.08, 0.3, 0.36], [0.58, 0.02, 0.86, 0.34]],
      "bubbles": [
        {"text": "妳上次說的，不要香菜。", "center": [0.45, 0.13], "tail": [0.66, 0.3]},
        {"text": "……記得這種事幹嘛。", "scale": 0.9, "rows": 5}
      ],
      "sfx": []
    }
  }
}
```

**座標**：這個檔的座標是相對於**組版後看到的格子**（裁切之後），比例 `[x, y]`／`[x0, y0, x1, y1]`，左上 (0,0)。和分鏡不同，因為這是人在成品上拖出來的位置。

### 格（key 是分鏡的格 id）

| 欄位 | 必填 | 說明 |
|---|---|---|
| `faces` | 否 | 這一格**所有**要避開的臉框。有寫就取代自動推估（`[]` 表示不避開任何東西）；沒寫就自動推估 |
| `bubbles` | 否 | 依分鏡 `bubbles` 的順序一一對應；不需要改的那一個寫 `{}` 或 `null`。比分鏡多出來的會被忽略並警告 |
| `sfx` | 否 | 依分鏡 `sfx` 的順序一一對應，寫法同上 |

### 對話框覆寫（`bubbles[]`）

| 欄位 | 預設 | 說明 |
|---|---|---|
| `text` | — | 存檔時的台詞，用來比對。分鏡的台詞改過、和這裡不同時，會警告「微調可能不適用」，但照樣套用 |
| `center` | 自動 | 對話框中心 `[x, y]`。有寫就固定在這裡，不再自動找位置（仍會限制在格子內） |
| `tail` | 自動 | 尾巴尖端 `[x, y]`；`null` 表示不要尾巴。旁白永遠沒有尾巴 |
| `scale` | `1.0` | 字級倍率 0.5–2 |
| `rows` | 自動 | 直排時每欄最多幾個字（橫排時是每行），1–40；用來改對話框的形狀 |

### 狀聲詞覆寫（`sfx[]`）

| 欄位 | 預設 | 說明 |
|---|---|---|
| `box` | 分鏡的 `box`（換算到格子） | 狀聲詞要填滿的框 |
| `angle` | `-8` | 旋轉角度（度，-45–45；正數是逆時針） |
| `vertical` | 自動 | `true` 直排、`false` 橫排；自動時框高大於寬就直排 |

### 嵌字規則

- **對話框形狀**：`speech` 橢圓、`thought` 雲狀＋小圓點、`shout` 爆炸鋸齒、`whisper` 虛線橢圓、`radio` 細密鋸齒的橢圓（電子音）、`narration` 直角方框。
- **直排**（`config.json` 的 `lettering.vertical`，預設 `true`）：欄由右到左，每欄置中。標點依台灣直排習慣：`，。、！？` 放在字格正中；`「」『』（）《》〈〉【】…—～：；` 轉 90 度；`！？`、`!?`、兩位以內的半形數字併成一格橫排（縱中橫）。
- **斷行禁則**：`，。、！？」』）…` 等不放在欄首（必要時懸在欄尾，最多一格）；`「『（` 等不放在欄尾；`……`、`——` 不拆開。
- **自動位置**：從 `anchor` 附近找格子內的空位，成本依序是：壓到臉（極高）、壓到其他對話框（極高）、閱讀順序顛倒、離 `anchor` 的距離、壓到角色身體。避不開臉時照樣放，但會警告。
- **閱讀順序**（M1 修正）：右翻時後一個對話框會先被讀到——整個在前一個上面、跑到右上方、或差不多高（起頭差 8% 內）但整個在右邊——就算顛倒。擺完全部對話框再檢查一次，顛倒的列警告（嵌字頁畫成紅框），手動固定的位置也一樣。在右下方、起頭明顯比較低的不算（讀者多半先往左讀）。
- **尾巴**：指向說話者臉框的下緣中央，尖端停在臉外；說話者沒有臉框（例如 `faces: []`）時指向他的 `box` 上緣。`offscreen` 的對話框見第 5 節（指向格框邊，`radio` 沒有尾巴）。
- **狀聲詞**：`sfx_mode = overlay` 時由嵌字疊上：黑字白邊、填滿框、預設稍微傾斜。`moss` 時交給 MOSS 畫，嵌字不處理。
- 字放不下（對話框比格子大）時，字級自動縮小到 0.6 倍為止，仍放不下就警告。

## 11. 原著 `source/chNNN.txt`（S5）

純文字或 Markdown，UTF-8。開頭的 YAML frontmatter 會被略過（方便從 Novel Studio 匯出）。整章會放進提示詞，太長時 `check_context()` 會擋下。

### 匯入切章（N2）

`tools/import.py`（核心 `t2c/importer.py`）可以把整本 `.txt`／`.md`／`.docx` 切成 `source/chNNN.txt`：

- 一章一個檔，檔名 `ch001.txt`、`ch002.txt`…（章號 1–999）。開頭第一行是 `# 第N章 章名`，空一行後是整理過的正文。
- 切章規則與 Novel Studio 的 `studio/importer.py` 相同：`第X章`／`Chapter N`／`Prologue` 等標題、Markdown `#` 標題、開頭目錄略過、同一章標題連寫兩次會合併；段落整理成一段一行、段間空一行，中文的場景分隔線統一成 `＊＊＊`。
- 重複匯入預設 `skip`（已存在的章號不動）；`overwrite` 會先備份到 `build/import/backup/<原檔名>.<YYYYMMDD-HHMMSS>.bak`（每章每種檔名最多留 10 份），再寫入 `chNNN.txt`。舊專案若是 `chNNN.md`，備份後會被 `.txt` 取代（`Project.source_path()` 以 `.txt` 優先）。
- 簡轉繁是選用：有裝 `opencc` 且指定 `convert` 才轉；沒裝就在結果的 `warnings` 說明並跳過。
- `.docx` 用標準函式庫讀 `word/document.xml`，不支援舊版 `.doc`。

`build/` 不進版控，備份也跟著不進版控。


  `signature` 是 `look_en`＋服裝句的雜湊；定案後又改了 `look_en` 或服裝，`status` 會標 ⚠ 過期，要重畫重挑。

## 17. 出圖 profile `config.json` 的 `comfy.profiles`（N4）

一組 profile ＝ 一種模型家族的一份完整出圖設定（workflow、模型檔名、取樣預設、負向、LoRA）。同一臺 ComfyUI 一次只能掛一組模型，所以換 profile 之前要先在 ComfyUI 換模型。

```json
"comfy": {
  "url": "http://127.0.0.1:8188",
  "default_profile": "moss",
  "profiles": {
    "moss": {
      "kind": "moss",
      "workflow": "",
      "models": {"unet": "moss_image_sft_int8_convrot.safetensors", "clip": "qwen3.5_9b_w4a8_gptq.safetensors", "vae": "flux2-vae_small.safetensors"},
      "negative": "",
      "default_preset": "final",
      "presets": {"final": {"steps": 25, "cfg": 2.5, "sampler": "er_sde", "scheduler": "simple"}}
    },
    "anima": {
      "kind": "anima",
      "models": {"unet": "UnstableAnima-Art-V4.safetensors", "clip": "qwen_3_06b_base.safetensors", "vae": "qwen_image_vae.safetensors"},
      "negative": "score_4, score_5, worst_quality, lowres, watermark",
      "default_preset": "final",
      "presets": {"final": {"steps": 12, "cfg": 1.8, "sampler": "er_sde", "scheduler": "beta"}}
    }
  }
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `kind` | 是 | `moss`（內建 `t2c/data/moss_layout.api.json`）或 `anima`（內建 `t2c/data/anima.api.json`）。 |
| `workflow` | 否 | 自訂的 API 格式 workflow；留空＝該 kind 的內建檔；相對路徑以 `config.json` 所在資料夾為準。 |
| `models` | 是 | `unet`／`clip`／`vae`，用 ComfyUI 列出的名稱（含子資料夾）。命名過的 profile **不繼承**頂層的 `comfy.models`。 |
| `presets` | 否 | 取樣設定（`steps`、`cfg`、`sampler`、`scheduler`、`lora`、`lora_strength`）；也**不繼承**頂層的 `comfy.presets`。 |
| `default_preset` | 否 | 這一組預設用哪個 preset。 |
| `negative` | 否 | 這一組的負向提示詞；專案的 `negative` 是空字串時才用它，workflow 自己的負向是最後一道。 |
| `loras` | 否 | 額外的 LoRA，接在 preset 的 `lora` 後面：`[{name, strength, on}]`，`on: false` 會跳過。 |

選擇順序：呼叫端指定（`tools/panels.py --profile`、介面與 API 的 `profile`）→ `project.yaml` 的 `comfy_profile` → `comfy.default_profile` → 只有一組就用那一組。

**沒有 `comfy.profiles` 的舊設定照舊可用**：頂層的 `comfy.workflow`／`models`／`presets`／`default_preset` 就等於一組叫 `moss` 的 profile（只有這種情況會用到頂層那幾個鍵）。

**設定頁（N6）只編一種格式**：舊設定在設定頁上顯示成「一組 moss 的 profile 卡」，按儲存時把頂層那幾個鍵搬成 `comfy.profiles.moss` 一起寫回（＝升級成新格式）。頂層鍵因為「一層合併」的寫檔規則會留在檔案裡，但只有沒有 `profiles` 的舊設定才會被讀到。模型下拉的清單來自 ComfyUI 的 `GET /object_info`（`t2c/comfy.py` 的 `available_models()`），不另外存檔。

檔名：`<格 id>_s<seed>[_<預設>][__<profile>].png`。不是 `default_profile` 的才加 `__<profile>`，所以同一格同一 seed 用兩個 profile 出圖不會互相蓋掉：`p001_k1_s1234.png`（預設 profile）、`p001_k1_s1234__anima.png`、`p001_k1_s1234_draft__anima.png`。候選清單、選圖、重畫都認這個後綴。

錯誤訊息會寫出是哪一組 profile、哪個鍵、哪個檔案：找不到 profile（列出有哪幾組）、`kind` 不認得（列出可用值）、workflow 檔不存在、缺模型檔名（指出 `comfy.profiles.<名稱>.models.<鍵>`）、找不到預設（列出該 profile 的 presets）、workflow 或版型 JSON 壞掉（指出第幾行第幾欄）。

## 18. 畫風預設集 `t2c/data/styles.json`（N5）

一部作品的畫風只有一個來源：`project.yaml` 的 `style_preset` 選一組，`t2c/styles.py` 的 `resolve(project.config)` 一次填好三個地方——生圖的 `style`（每格 caption 最前面）、MOSS 的 `summary.meta`、文字端提示詞的畫風描述 `look`（「日式黑白頁漫」那一段）。所以換預設集是「一次換整本書的畫風」，不會出現提示詞說黑白、`style` 卻叫你畫彩色這種自相矛盾。

| key | 名稱 | 生圖 `style` | `meta` | 提示詞 `look` | 組版 `gray` |
|---|---|---|---|---|---|
| `mono` | 日式黑白頁漫 | 黑白線稿＋網點 | `manga panel, black and white, screentone` | 日式黑白頁漫 | `true` |
| `color` | 彩色日式頁漫 | 彩色日漫賽璐璐上色 | `manga panel, full color, cel shading` | 彩色日式頁漫 | `false` |
| `american` | 美式彩色漫畫 | 美式漫畫、粗黑線、網點陰影 | `comic panel, american comic book, full color` | 美式彩色漫畫 | `false` |

- 每組五個欄位：`style`、`meta`、`look`、`sfx`（狀聲詞交給 MOSS 畫時的英文描述）、`gray`（組版要不要轉灰階）。`sfx` 一起換，黑白是 black ink、彩色是 colored fill。
- **`gray`（1.12.2 起只是建議值）**：這組畫風「通常要不要灰階」的說明。組版**不會**自動套用——要不要灰階由 `project.yaml` 的 `output.gray` 決定（預設保留原色），`tools/pages.py` 的 `--gray`／`--color` 只覆寫那一次執行。注意 `gray: true` 只是「把顏色拿掉」，不是「畫成黑白漫畫」；要黑白頁漫請選 `mono` 畫風。
- 覆蓋是**逐欄**的：`project.yaml` 明寫 `style`／`meta`／`look`／`sfx` 只蓋掉那一欄，其餘照預設集。範例專案就是明寫 `style`＋`meta` 的老寫法，行為不變。
- 名稱不認得或預設集檔壞掉時，`styles.StylesError` 會列出可用的 key：`沒有這組畫風「watercolor」（可用：american、color、mono）`。
- 新增一組：在 `presets` 加一個鍵、四個欄位寫齊即可，不必改程式。
- 美式目前只換畫風，**閱讀方向仍是右翻**（`reading: rtl`）；左翻是另一件事。

## 19. 反推的排程檔 `build/reverse/`（N5）

從原著反推視覺聖經草稿時的續跑紀錄（`build/` 不進版控）：

```
build\reverse\state.json                 跑到第幾章、這次幾批、有沒有被停止
build\reverse\accumulated.json           跨批累積：已完成的章號、角色、地點（含各章的外觀與服裝原句）
build\reverse\batches\第NNN-NNN章.json   每批的原始掃描輸出
```

- 一批最多 3 章（`reverse.MAX_PER_BATCH`）；每章成本用 `llm.estimate_tokens` 估，超過 `budget - out_reserve`（預設 32768 − 8192）就換批，至少一批一章。
- 續跑以**單章**為單位：累積檔有、且 `build/bible/scan/chNNN.json` 的 `sha1` 與現在原文相同才跳過。刪掉中間某一章的掃描快取，下一次只重掃那一章；`--force` 才把累積歸零、全部重掃。
- 抽取與成卡仍走 `t2c/bible.py`（`Builder.scan()`／`Builder.draft()`），草稿只寫 `bible/drafts/`；按「採用」（`bible.accept()`）才進 `bible/characters|locations/`。
- 命令列：`tools/reverse.py`，`--dry-run` 只印批次計畫（不呼叫模型、不寫檔）。
