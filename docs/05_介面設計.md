# 介面設計（S7）

目標：**不碰命令列完成一章**——開專案 → 原著 → 改編規劃 → 劇本 → 分鏡 → 逐格出圖、挑圖 → 嵌字 → 頁面。命令列工具（`tools/*.py`）照舊可用，介面和它們呼叫同一批 `t2c` 函式。

## 1. 原則

1. **核心不知道介面**：介面需要、命令列也用得到的邏輯放 `t2c/`（`workspace.py`、`render.py`、`gpu.py`）；`server/` 只做參數檢查、錯誤轉成 `ApiError`、把核心包成背景任務。
2. **專案由瀏覽器記住**：目前開的漫畫專案資料夾存在瀏覽器（`FE.store` 的 `project`），每個 API 都帶 `project`（資料夾路徑）。後端不存「目前專案」，所以重新啟動、開兩個分頁都不會亂。最近開過的專案也記在瀏覽器。
3. **人的決定立刻存檔，產出另外產生**：挑圖、裁切焦點按了就寫 `picks/`；分鏡、劇本、原著、聖經卡片按「存檔」才寫；頁面 PNG 由「輸出頁面」任務產生。
4. **長工作一律是背景任務**（LLM、出圖、整章組版），進度顯示在右邊的任務面板，可以停止。任務**排隊執行、同時只跑一個**（`JobRunner(queue=True)`），所以 LLM 與 ComfyUI 不會被本工具同時叫起來。
5. **人改的檔案只擋「編譯不了」**：LLM 的輸出要過全部檢查（CLAUDE.md 規則 6）；人在介面改的分鏡只要能 `compile_chapter()` 就能存，其他檢查（外觀字、每行字數、和劇本不一致）列成提醒，人自己決定。劇本、原著、卡片也一樣：存檔後顯示檢查結果，不擋。
6. 介面文字繁體中文；檔案、欄位、CSS class 英文。

## 2. 頁面

一個入口一件事（LAYOUT A，`docs/06_決策記錄.md` D5）：中間永遠只放剛按下去的那一個功能，不並排三個表單。

| 網址 | 頁面 | 內容 |
|---|---|---|
| `#/new` | 新建專案 | 資料夾路徑、作品名、畫風預設集、從範例複製（可連同範例的出圖） |
| `#/projects` | 開啟專案 | 路徑或瀏覽、最近開過（第一次開工具時落在這裡） |
| `#/project` | 總覽 | 章節表與各階段進度、畫風（換了寫回 `project.yaml`）、匯入整本切章、視覺聖經摘要；開不了專案時給「換一個專案／新建專案」的出口 |
| `#/chapter/:n` | 章節 | 分頁（`?tab=`）：原著、**切對話**、規劃、劇本、分鏡、出圖、頁面；頂端「整章批次」 |
| `#/bible` | 視覺聖經 | 草稿（本文＋原文引文並排、改卡片、確認入庫）、定案卡片（**分段編輯器**、定裝圖候選、挑選、重畫）、**過期格清單與只重畫過期格**、抽取任務、**反推設定（整本掃描＋成卡）與進度** |
| `#/letter` | 嵌字 | S3 的頁面；沒帶 `project` 時用目前專案。右翻順序顛倒的對話框畫成紅框（M1 修正） |
| `#/settings` | 設定 | 環境（ComfyUI 連線、各 provider 的金鑰／狀態／用在、設定檔與出圖預設）、provider 與階段、出圖 profile、嵌字 |

`#/` 是舊網址（書籤、文件裡的連結）：有專案就導到 `#/project`，沒有就導到 `#/projects`。沒開專案就進 `#/chapter/:n`、`#/bible`、`#/letter` 時，頁面顯示「還沒有開啟漫畫專案」並給 `#/projects` 的連結，不是報錯。

### 左側導覽

- 三段：**專案**（新建專案、開啟專案）、**目前的專案**（總覽、第 N 章、視覺聖經、嵌字）、**系統**（設定）。
- 沒有專案時，中間那一段只剩「（尚未開啟專案）」一行，工作入口完全不出現（`web/static/app.js` 的 `nav()` 每次換頁重算，專案換了用 `t2c-project` 事件刷新）。
- 子項縮排只用 `web/static/app.css` 的屬性選擇器（`a.nav-item[href="#/project"]`、`[href^="#/chapter/"]`、`[href="#/bible"]`、`[href="#/letter"]`）：fekit 的導覽是「扁平項目＋一個分組標題」，沒有層級也沒有徽章，`vendor/fekit/` 不動（D5）。
- 底部狀態列（`slots.nav_foot`）一行顯示 ComfyUI 連不連得上與缺哪些金鑰，右邊一顆「重新檢查」；狀態不放進入口名稱（沒有徽章可用）。

### 分段卡片與過期格（步驟 2）

- **卡片編輯頁**（`#/bible/:kind/:id`）：最上面是「分段」區塊——五段（頭部／身形／上半身／下半身／飾品）各一個輸入框，一行一個英文短語；下面是每一套服裝一張小卡（上著／下著／套裝三行＋中文說明）。按「儲存分段」走 `POST /api/bible/card/sections`（後端改寫 frontmatter、本文照舊），旁邊附「這個鏡頭會用到哪幾段」的對照表。舊格式（只有 `look_en`）的卡片整區顯示提示，旁邊一顆「**拆成分段（草稿）**」：`POST /api/bible/card/split` 用文字規則（`t2c/bible.split_look()`）把 `look_en` 與整句服裝拆進五段與服裝小卡，**不寫檔**，人看過、改過再按「儲存分段」才會落地。frontmatter 的 YAML 文字框留著當進階。
- **視覺聖經首頁**：多一張「過期格」卡（`GET /api/bible/stale`）——「有 N 格過期」，每章一列（章號、格 id、原因、候選張數），一顆「只重畫這些格…」按 `POST /api/task/render` 帶 `stale: true`。原因寫的是「哪一個角色的哪一段改了」（`下半身`／`上著`／`畫風`…），不是籠統的「過期」。
- **出圖分頁**：每一格顯示探索用 chip（這一格有角色還沒有卡片）並停用選圖；頂端多一組篩選：全部／只看過期／只看探索用／只看已選。
- **探索用（D2）**：缺卡也能出圖，但那一格不進 `picks/`、不進頁面、不列入過期清單；卡片補上後才變成可以正式出圖的格。

### 切對話的分頁（步驟 3）

- **沒切過**：一句說明（小說 → 場 → 旁白／對話／演出，每句回指原著段落；台詞逐字、漏句自動補）＋「產生切對話（模型）…」，按了跑 `POST /api/task/adapt` 的 `stage: "annotate"`，進度在右側任務面板。
- **切過**：標題、「重新切一份（覆蓋）」（`force: true`）、每一場一列（場號、標題、行數），展開看每一行的種類（旁白／對話／演出）、說話者、文字與「原文第 N 段」；忠實度報告（`GET /api/chapter/scenes` 的 `fidelity`）收在 `<details>`。
- 任務結束時 `refresh` 有 `annotate` 就重新載入這一頁。
- 整章批次的階段清單多了「切對話」，它排在規劃前面（`server/tasks.py` 的 `STAGES` 決定執行順序）。

### 反推設定（步驟 4）

- 視覺聖經首頁的按鈕列多一顆「反推設定（整本掃描＋成卡）…」：到第幾章、至少出現幾章才成卡、每批 token 預算、重新掃描全部章節；按「開始」跑 `POST /api/task/reverse`，進度（計畫／每批／存檔／草稿／停止）在右側任務面板。
- 首頁多一張「反推進度」（`GET /api/bible/reverse`）：已完成章數、批次數、跳過幾章、草稿張數、最後更新時間；上次被停止會寫「可以接著跑」。草稿的 id 直接連到草稿卡片。
- **採用就是既有的草稿卡**：反推只寫 `bible/drafts/`，要人看過、按「確認入庫」才會進定案。

### 章節的分頁

- **原著**：貼上或從檔案匯入（`source/chNNN.txt`），顯示字數與 token 估計。
- **規劃**：表格看每頁每格的節拍與原著依據、刪減清單、聖經缺的人物；「產生規劃」任務（可指定頁數、章名）；進階：直接改 JSON（存檔前過 `check_plan`，有錯擋下）。
- **劇本**：Markdown 檢視／編輯；「產生劇本」任務（全部，或只重寫某一頁）；忠實度報告。
- **分鏡**：一頁一張表，一格一列（鏡頭、角度、地點、畫面、角色、台詞）。點一列打開這一格的編輯區（對話框可勾「畫面外」：說話的人不在這一格，或透過通訊說話，這時說話的人可以選不在場的角色；M1 修正）：欄位表單＋框編輯器（在這一格的比例畫布上拖角色框、物件框、狀聲詞框、對話框 anchor；有選圖就用它當底圖），以及編譯後送給 MOSS 的提示詞。「產生分鏡」任務（全部或某一頁）。
- **出圖**：頂端先是狀態一行，接著**出圖 profile（哪一組模型）**、再**出圖預設（步數／cfg，清單是那一組 profile 自己的）**，各自一行；按鈕與篩選（全部／只看過期／只看探索用／只看已選）另起一列。探索用的格顯示 chip 並停用選圖。一格一張卡片，列出候選縮圖；點縮圖＝選圖（立刻寫 `picks/`）；裁切編輯（拖焦點、調放大，即時看到格子裡的樣子）；「出圖」任務：整頁、只這一格、加畫 N 張（新 seed）、同 seed 重畫；出圖預設（`final`／`draft`）。
- **頁面**：每頁的嵌字預覽（即時組版＋嵌字，不寫檔）、到嵌字頁微調、「輸出頁面」任務（寫 `pages/chNNN/`）。**下載（S8）**：整章 PDF／CBZ 與每頁的「這頁 PDF」，用已輸出的頁面 PNG 打包（右翻，格式見 `docs/02_資料格式.md` 第 15 節），同時存在專案的 `out/`；頁面 PNG 沒輸出齊時按鈕停用並說明原因，PNG 比分鏡／選圖／嵌字舊時顯示提醒；可勾「PDF 用單頁檢視開啟」。打包很快（幾秒），所以是同步下載，不走背景任務。

## 3. 新 seed 怎麼來（「加畫」）

seed 仍由格子 id 決定（`compile._seed(格 id, 候選編號)`，CLAUDE.md 規則 7）。「加畫 N 張」從候選編號 0 往上找，跳過檔案已經存在的，取前 N 個——所以加畫的結果也可重現，且不會覆蓋任何舊圖。「同 seed 重畫」只在明確選了某一張時提供（會覆蓋該檔）。

## 4. VRAM 排程（`t2c/gpu.py`）

本機 llama.cpp 與 ComfyUI 不同時佔 GPU（16 GB 放不下兩邊）：

1. 任務排隊、一次一個（見原則 4）。
2. **呼叫本機 LLM 前**：對 ComfyUI 送 `POST /free`（`unload_models`、`free_memory`），把模型卸下。ComfyUI 沒開就略過。
3. **出圖前**：檢查設定裡的本機 provider（網址是 localhost）是否還在執行（`GET /health`）。還在的話，任務**暫停並詢問**：關掉 llama-server（或卸載模型）後按「繼續」；也可以選「照樣出圖」或「停止」。用 DeepSeek 時沒有這一步。
4. 整章批次依序：規劃 → 劇本 → 分鏡（LLM）→（第 2、3 點）→ 出圖 → 輸出頁面。每一步都會跳過已經有的檔案（除非勾「重做」），中途停止後再按一次會接著做。

llama-server 目前沒有通用的「卸載模型」API（只有 router 模式有），所以第 3 點用詢問而不是自動卸載（記在 backlog）。

## 5. API（`server/`）

所有端點都帶 `project`（GET 用 query、POST 用 body）。錯誤用 `ApiError(400, 訊息, code)`。

|---|---|---|
| GET | `/api/project` | 專案總覽：設定、章節表、聖經摘要 |
| POST | `/api/project/create` | 新建專案（`path`、`title`、`style`；`from_sample: true` 複製範例） |

| POST | `/api/task/adapt` | 任務：規劃／劇本／分鏡（`stage`、`pages`、`page`、`force`） |
| POST | `/api/task/render` | 任務：出圖（`page`、`panel`、`more`、`seed`、`preset`、`force`） |
| POST | `/api/task/pages` | 任務：輸出頁面 |
| GET | `/api/chapter/pages` | 每頁的模板、格數、已輸出的 PNG；`export` 欄位：能不能下載（`ready`、`message`、`warnings`） |
| GET | `/api/chapter/export` | 下載 PDF／CBZ（`format`、`page` 省略＝整章、`quality`、`lossless`、`single`）；同時存在 `out/` |
| POST | `/api/task/batch` | 任務：整章批次（`stages`、`force`、`preset`） |
| GET | `/api/bible` | 聖經：定案卡片、草稿、檢查結果、定裝圖狀態 |
| GET／POST | `/api/bible/card` | 讀寫一張卡片（整個 Markdown 檔；存檔後回傳檢查結果） |

| GET | `/api/bible/renders` | 一個角色或地點的定裝圖候選 |

| POST | `/api/llm/probe` | 測一個 provider 的連線（內部用 `llm.list_models()`）：`{ok, models, ms, message}`，失敗也是 HTTP 200 |
| POST | `/api/llm/key` | 把金鑰存進系統金鑰庫（`keyring.set_password("novel-studio", provider id, key)`）：**不寫任何檔案**；環境變數仍優先 |

## 6. 任務完成後的畫面更新

任務的 `result` 帶 `{"refresh": ["storyboard", ...], "project": …, "chapter": …}`。頁面用 `FE.jobs.onend()` 訂閱，是同一個專案、同一章才重新載入資料；離開頁面時取消訂閱。
