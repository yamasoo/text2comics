# 文字轉漫畫 階段計畫

一個對話做一個階段；完成後依 `CLAUDE.md` 第 6 節回報下一階段的建議模型與思考強度。

## 主線與範圍

**主線：先把獨立工具做到「一章小說 → 可讀的黑白頁漫 PDF」，再分別整合進 Novel Studio 與 t2vn。**

| 在範圍內 | 不在範圍內 |
|---|---|
| 改編、漫畫劇本、分鏡、逐格出圖、嵌字、組版、輸出 | 彩色漫畫、條漫（webtoon）、四格（之後再評估，記 backlog） |
| DeepSeek、llama.cpp（OpenAI 相容 API） | Claude API（本工具刻意不用 Claude 資源） |
| MOSS-Image（ComfyUI） | 其他出圖模型（Anima 等留給 Novel Studio 既有機制） |
| 兩個整合**計畫**＋在各自專案的對話中實作 | 在本專案的對話裡直接改另外兩個專案 |

先做出圖與組版、再做 LLM 文字端：出圖的限制（角色一致性、格子比例）會反過來決定分鏡要寫什麼，先驗證才不會白寫提示詞。

## 模型選擇原則

| 情況 | 建議 |
|---|---|
| 定資料格式、提示詞架構、版面規則，錯了後面全部要改 | Opus 5.5，high |
| 依既定規格實作 | Sonnet 5.5，medium |
| 照範例重複的工作、補文件 | Sonnet 5.5，low–medium；或外包 DeepSeek |
| 讀大量既有程式才能寫的整合計畫 | Opus 5.5，high |
| 里程碑獨立驗收（不能讓做的人自己驗） | 另開對話，Opus 5.5，high |
