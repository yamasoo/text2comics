# 文字端提示詞設計（S5）

小說一章 → ① 改編規劃 → ② 漫畫劇本 → ③ 分鏡 JSON。程式在 `t2c/prompts.py`（提示詞）、`t2c/script.py`（劇本解析、忠實度）、`t2c/check.py`（驗證）、`t2c/adapt.py`（流程、回修）；命令列 `tools/adapt.py`。

## 1. 分工：LLM 只做需要理解故事的事

| 階段 | LLM 做 | 程式做 |
|---|---|---|
| ① 規劃 | 分頁、選模板、每格演什麼（beat）、刪了什麼 | 檢查模板存在、格數、角色／地點 id |
| ② 劇本 | 每格的畫面描述、鏡頭詞、台詞取捨 | 解析、格數、鏡頭詞、說話者對得到聖經、每格 ≤ 3 個對話框；統一標題行；忠實度報告 |
| ③ 分鏡 | 構圖：鏡頭、角色框、物件、對話框位置、英文 scene／pose | 逐字比對台詞、id、座標範圍、英文欄位、外觀詞、每欄字數；補 `id`；最後 `compile_chapter()` |

角色外觀、座標換算、seed 仍然只由程式處理（CLAUDE.md 規則 2、3、7）。

參考 lhfer/codex-novel-to-comic-studio（MIT）的分工：先規劃每頁要給讀者什麼、再寫劇本、再分鏡，每一步都有驗證。只借流程，沒有複製它的文字；它最後讓 image2 整頁生成並畫字，本工具則是一格一張圖、嵌字另外疊。

## 2. 為什麼這樣切

- **劇本是分鏡的唯一依據**：分鏡階段只看劇本、不看原著，台詞逐字比對。人改了劇本再重跑分鏡，結果一定跟著改；也不會出現「劇本一套、分鏡另一套台詞」。
- **逐頁產生**（劇本、分鏡）：一頁出錯只重做那一頁；輸出短，小模型（llama.cpp）也比較穩；`--page N` 可以只重做一頁，其他頁（含人改過的）不動。
- **可快取的前綴**：同一階段每次呼叫的開頭（規則、範例、聖經、原著）完全相同，只有最後「本頁任務」不同；每次只送 system＋一則 user（有些本機模型的聊天模板不接受連續兩則 user）。DeepSeek 的硬碟快取與 llama-server 的 prompt cache 都會吃到前綴。
- **上下文接續**：劇本提示詞附上一頁的劇本；分鏡提示詞附上一頁各格的 scene。

## 3. 驗證與回修

1. 產生 → 驗證。JSON 語法錯誤先由 `llm.chat_json()` 回修一次。
2. 有 **error** 就把**全部**錯誤（寫明第幾頁第幾格）接在模型上一次的輸出後面回給它：`system, user, assistant(上次輸出), user(錯誤清單)`。每一輪都從原始提示詞重來，對話不會越來越長。
3. 最多 `max_fix` 輪（預設 3）。還是不過就丟 `AdaptError`，最後一次輸出存在 `build/adapt/chNNN/<階段>_第 N 頁.txt`。
4. **warn** 不回修，只在結束時列出（例如鏡頭詞和劇本不一致、兩個角色都在畫面中間、多餘欄位已忽略）。
5. 分鏡全部通過後再跑一次 `compile_chapter()` 當最後關卡；過了才寫檔。

### 分鏡的主要規則（`check.py`）

| 規則 | 理由 |
|---|---|
| 台詞、旁白、狀聲詞和劇本逐字相同（不計空白、`\n`） | 劇本是人審過的版本 |
| 劇本有標語氣（心聲／喊／小聲）或旁白時，`kind` 必須照做；沒標的一般台詞可以是 speech、shout、whisper | 分鏡師看得出大喊（範例 k3） |
| 每一行（直排是每一欄）≤ 12 字，旁白 ≤ 16 字，超過要加 `\n` | 嵌字沒有中文斷詞（S3 backlog） |
| scene、pose、expression、objects.caption 要英文 | 生圖提示詞用英文 |
| scene、pose、expression 不准出現 wear／dressed in／「顏色或長短＋hair／eyes」／bangs、ponytail | 外觀只來自聖經（規則 3） |
| 說話者必須在這一格的 characters | `compile` 的規定；畫面外說話就把框放邊緣 |
| 座標 0–1、左上小於右下；anchor 是兩個 0–1 的數 | 座標只有一種（規則 2） |
| 角色、地點、服裝 id 要在聖經 | 編譯時要查 |
| 每格最多 3 個對話框 | 可讀性 |

`id` 一律由程式補成 `p<頁>_k<格>`，模型寫的會被覆蓋；`seeds` 與其他欄位會被丟掉（列在提醒）。

## 4. 提示詞內容

都在 `t2c/prompts.py`，用 `python tools/adapt.py <專案> <章> --stage <階段> --show-prompt [--page N]` 可以直接看送出去的全文。

- **共用 system**：責任編輯兼分鏡師、日式右翻黑白頁漫、只輸出指定格式、繁體中文（台灣用語）。
- **模板清單**由 `layouts/pages.json` 自動產生，每格標出位置與形狀（例：`1 格 上右·略橫`），新增模板不用改提示詞。
- **範例**用虛構角色（阿杰、小晴，模板 2h），測試會確認範例本身能通過所有檢查並能編譯，避免範例教錯。
- **視覺聖經**：規劃與劇本階段給姓名、別名、服裝 id 與角色設定（本文前 200 字）；分鏡階段另給 `look_en`，只供判斷性別年齡、選代稱，並明寫禁止複述。

## 5. 忠實度報告

劇本階段結束會寫 `build/adapt/chNNN_fidelity.md`（不進版控）：

- 劇本台詞有幾句能在原著逐字找到（不計標點）；找不到的列出來（改寫或新增）。
- 原著引號「」『』“” 內的句子有幾句進了劇本；沒進的列出來（刪除或改寫）。

這只是給人工評分用的線索，不擋流程。

- **llama.cpp**：使用者指示 S5 先不測。
- **思考模式（`reasoning`）**：`config.example.json` 沒開。建議實測時比較 `adapt` 開 high 與關閉的規劃品質；`script`、`storyboard` 先關（輸出格式為主，思考只會變慢）。
- 長章節：原著整章放進提示詞；超過上下文時 `check_context()` 會擋下並說明，分段處理記在 backlog。
